# Gym Bro 機能一覧(旧称: 筋トレメモ)

「筋トレ版Strava」を目指し、まず**記録(筋トレメモ)**を固め、その上に**友達共有**を載せる。
優先度: ◎=MVP必須 / ○=v1.x / △=将来

## 1. 記録(筋トレメモ本体)

| 機能 | 内容 | 優先 |
|---|---|---|
| ワークアウト作成 | 日付・開始/終了時刻・タイトル・メモ | ◎ |
| 種目の追加 | 種目マスタから選択、またはその場でカスタム種目作成 | ◎ |
| セット記録 | 重量(kg)・回数・セット数、セット単位で追加/削除/複製 | ◎ |
| 前回記録の表示 | 同種目の前回の重量×回数を入力欄の近くに表示 | ◎ |
| ワンタップ入力 | 前セットのコピー、±ボタンで重量/回数を増減 | ◎ |
| 種目マスタ | 部位別(胸/背中/脚/肩/腕/腹)、器具別(バーベル/ダンベル/マシン/自重)のプリセット | ◎ |
| 履歴一覧・カレンダー | 日付ごとの実施有無、過去ワークアウトの閲覧・編集・削除 | ◎ |
| インターバルタイマー | セット間休憩タイマー(秒数プリセット、終了通知) | ○ |
| ルーティン/テンプレート | 「胸の日」などメニューを保存し、ワンタップで開始 | ○ |
| RPE/RIR・セット種別 | ウォームアップ/ドロップセット/failure のタグ | ○ |
| 有酸素・時間系種目 | 時間・距離で記録する種目タイプ | ○ |
| 体重・体組成ログ | 体重、体脂肪率、ボディ写真(任意) | ○ |
| 写真/動画添付 | ワークアウトにジム写真・フォーム動画 | △ |
| 単位切替 | kg/lb | △ |

## 6. 非機能要件

- **無料運用**: 無料枠で収まる構成。広告・課金なしが前提(将来の収益化は別途検討)。
- **Claude非依存**: 開発・運用・実行のどこにもClaude/AI APIを必須としない。コードは通常のOSSスタックで、人間が保守できる構成にする。
- **PWA優先**: ストア審査/年会費($99/年など)を避けるため、まずPWA(ホーム画面に追加)で提供。
- **プライバシー**: 既定は非公開寄り。位置情報は扱わない。
- **データ可搬性**: いつでも全データをエクスポート可能。

## 7. 技術案(無料・Claude非依存)

| 層 | 候補 | 備考 |
|---|---|---|
| フロント | SvelteKit または React + Vite(PWA) | どちらも一般的OSS |
| ホスティング | Cloudflare Pages / Vercel / GitHub Pages | 無料枠あり |
| バックエンド・DB・認証 | Supabase(Postgres+Auth+RLS) または Firebase | 無料枠あり。フレンド/フィードはリレーショナルなSupabaseが相性良 |
| ローカル保存 | IndexedDB(Dexie) | オフライン記録用 |
| 画像生成(共有カード) | クライアント側 canvas | サーバー費用ゼロ |

※無料枠の上限(Supabaseは一定期間無操作でpause等)は採用前に最新の規約を確認すること。

## 8. 提案する開発ステップ

1. **Phase 1(ローカル完結)**: 記録・履歴・種目マスタ・PR・グラフ・エクスポート(アカウント不要、IndexedDB)
2. **Phase 2(共有)**: 認証・フレンド・フィード・リアクション・公開範囲・同期
3. **Phase 3(磨き込み)**: コメント、通知、リーダーボード、共有カード、チャレンジ

## 9. 決定事項(ユーザー回答)

- **規模**: 友人数人。→ 招待制のクローズド運用。モデレーション/通報/ブロック、公開範囲「全体公開」、大規模向けランキングは不要(優先度を下げる)。無料枠に余裕で収まる。
- **提供形態**: PWA。
- **対象**: 重量トレに加え**有酸素も対象**(Phase 1から種目タイプ「重量×回数」「時間・距離」を持つ)。
- **技術**: 指定なし → **React + Vite + TypeScript(PWA。スタイルはデザイントークンを使った素のCSS)**、データは IndexedDB(Dexie)、共有フェーズで Supabase を採用。デジタル庁のデザインシステムが React/Tailwind 向けのサンプル実装とデザイントークンを公開しているため相性が良い。
- **UI**: 当初はデジタル庁デザインシステム参考としたが、**Notion風・2色(文字色+青)・英語表記**に変更(Phase 2で反映)。タップ領域44px以上・フォーカス表示などのアクセシビリティ配慮は維持。

### 9.1 有酸素の扱い
- 種目タイプ: 重量系(重量・回数)/ 有酸素系(時間・距離、任意で心拍・消費kcal・ペース自動計算)/ 自重系(回数のみ)
- 有酸素プリセット: ランニング、ウォーキング、サイクリング、水泳、ローイング、エアロバイク、ジャンプロープ
- 集計: 週間の総時間・総距離、ペース推移、ベスト(最長距離・最速ペース)
- フィード: 有酸素は「距離・時間・ペース」を表示

### 9.2 フレンド共有(友人数人向けに簡素化)
- 招待リンク/コードでのみ参加・友達追加(ユーザー検索は不要)
- 公開範囲は「自分のみ / 友達」の2択
- フィード+リアクション+コメントをMVP共有機能とし、リーダーボード・チャレンジは任意の後回し

### 9.3 UI方針(当初案。現在は上記のとおりNotion風に変更)
- 公式: https://design.digital.go.jp/ (デザインシステム/ デザイントークン / Figma)。着手時に最新版を必ず確認し、ライセンス・利用条件も確認する。
- 方針
  - 文字: Noto Sans JP、本文16px以上、行間広め
  - 色: 青系の主色、ニュートラルグレー、状態色(エラー/成功/警告)をトークン化。**文字コントラストはWCAG 2.1 AA以上**(色だけで意味を伝えない)
  - フォーカスリング: 視認しやすいはっきりした枠を常に表示
  - タップ領域: 最小44px角(ジムで汗をかいた手でも押しやすい)
  - コンポーネント: ボタン、フォーム入力、ラジオ/チェック、セレクト、タブ、ダイアログ、ステータス/エラー表示を、公式のコンポーネント仕様に沿って実装
  - 平易な日本語、ラベルは入力欄の上、エラーは原因と対処を明記
  - アクセシビリティ: キーボード操作、スクリーンリーダー、ダークモードは後回し
- 実装: 公式のデザイントークン(npm配布のものがあればそれ)を CSS変数(src/styles.css)に取り込み、色・余白・文字を一元管理

## 10. 改訂版の開発ステップ

1. **Phase 1(ローカル完結)**: ワークアウト記録(重量・有酸素)、種目マスタ、履歴、PR、グラフ、JSON/CSVエクスポート、PWA/オフライン、デザイントークン適用
