# 筋トレメモ(仮) 機能一覧

「筋トレ版Strava」を目指し、まず**記録(筋トレメモ)**を固め、その上に**友達共有**を載せる。
優先度: ◎=MVP必須 / ○=v1.x / △=将来

## 1. 記録(筋トレメモ本体)

| 機能 | 内容 | 優先 |
|---|---|---|
| ワークアウト作成 | 日付・開始/終了時刻・タイトル・メモ | ◎ |
| 種目の追加 | 種目マスタから選択、またはその場でカスタム種目作成 | ◎ |
| セット記録 | 重量(kg)・回数・セット数、セット単位で追加/削除/複製 | ◎ |
| 前回記録の表示 | 同種目の前回の重量×回数を入力欄の近くに表示 | ◎ |
| ワンタップ入力 | 前セットのコピー、±ボタンで重量/回数を増減 | ◎ |
| 種目マスタ | 部位別(胸/背中/脚/肩/腕/腹)、器具別(バーベル/ダンベル/マシン/自重)のプリセット | ◎ |
| 履歴一覧・カレンダー | 日付ごとの実施有無、過去ワークアウトの閲覧・編集・削除 | ◎ |
| インターバルタイマー | セット間休憩タイマー(秒数プリセット、終了通知) | ○ |
| ルーティン/テンプレート | 「胸の日」などメニューを保存し、ワンタップで開始 | ○ |
| RPE/RIR・セット種別 | ウォームアップ/ドロップセット/failure のタグ | ○ |
| 有酸素・時間系種目 | 時間・距離で記録する種目タイプ | ○ |
| 体重・体組成ログ | 体重、体脂肪率、ボディ写真(任意) | ○ |
| 写真/動画添付 | ワークアウトにジム写真・フォーム動画 | △ |
| 単位切替 | kg/lb | △ |

## 6. 非機能要件

- **無料運用**: 無料枠で収まる構成。広告・課金なしが前提(将来の収益化は別途検討)。
- **Claude非依存**: 開発・運用・実行のどこにもClaude/AI APIを必須としない。コードは通常のOSSスタックで、人間が保守できる構成にする。
- **PWA優先**: ストア審査/年会費($99/年など)を避けるため、まずPWA(ホーム画面に追加)で提供。
- **プライバシー**: 既定は非公開寄り。位置情報は扱わない。
- **データ可搬性**: いつでも全データをエクスポート可能。

## 7. 技術案(無料・Claude非依存)

| 層 | 候補 | 備考 |
|---|---|---|
| フロント | SvelteKit または React + Vite(PWA) | どちらも一般的OSS |
| ホスティング | Cloudflare Pages / Vercel / GitHub Pages | 無料枠あり |
| バックエンド・DB・認証 | Supabase(Postgres+Auth+RLS) または Firebase | 無料枠あり。フレンド/フィードはリレーショナルなSupabaseが相性良 |
| ローカル保存 | IndexedDB(Dexie) | オフライン記録用 |
| 画像生成(共有カード) | クライアント側 canvas | サーバー費用ゼロ |

※無料枠の上限(Supabaseは一定期間無操作でpause等)は採用前に最新の規約を確認すること。

## 8. 提案する開発ステップ

1. **Phase 1(ローカル完結)**: 記録・履歴・種目マスタ・PR・グラフ・エクスポート(アカウント不要、IndexedDB)
2. **Phase 2(共有)**: 認証・フレンド・フィード・リアクション・公開範囲・同期
3. **Phase 3(磨き込み)**: コメント、通知、リーダーボード、共有カード、チャレンジ

## 9. 確認したい点(未決事項)

- 想定ユーザー規模(自分+友人数人か、不特定多数に公開するか)→ 公開範囲やモデレーション要否が変わる
- 提供形態: PWAで十分か、ネイティブアプリ(App Store/Google Play)が必要か
- 使う技術の好み・経験(React/Svelte/Flutter 等)
- 重量トレ以外(有酸素・ヨガ等)も対象にするか
